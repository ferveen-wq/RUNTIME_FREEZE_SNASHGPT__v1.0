# Deferred UAT Packs

These packs were deferred from promotion because they need reclassification before becoming official UAT authority.

Reasons include:
- input-only assertions where runtime-signals should be used
- phase naming that may not match actual executable ownership
- multi-turn expectations on a harness shape that is historically not fully trustworthy
- old assumptions that may belong to earlier patch stages

Promotion rule:
- only promote after reclassification
- define executable owner
- define validation method
- avoid parallel or misleading UAT authority
